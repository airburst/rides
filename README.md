# Rides App

A modern SPA for cycling clubs to plan, discover, and manage group rides and events. Supports multiple clubs via subdomain routing with per-club branding (colors, logos).

## Stack

- **Framework**: TanStack Start (SPA mode, hybrid SSR for root layout) + Vite
- **Runtime**: Bun
- **UI**: React 19, ShadCN, Tailwind CSS 4
- **State**: TanStack Query (server), React Context (UI)
- **Routing**: TanStack Router (file-based)
- **Forms**: react-hook-form + Zod
- **Auth**: Auth0 (legacy) / better-auth (new clubs - future)
- **Backend API**: Hono (external service)

## Quick Start

```bash
bun install
bun run dev          # Dev server on http://localhost:3000
bun run build        # Production build
bun run check-types  # Type check
bun test             # Run tests
bun run lint         # Lint + fix
```

## Architecture

- **Multi-club support**: One deployment serves all clubs; detected by subdomain (`bath.example.com`, `shrewsbury.example.com`)
- **Theme generation**: Each club has a per-club CSS theme file generated by rides-admin
- **SSR hybrid**: Root layout SSR-renders to inject theme CSS at request time (no FOUC); routes hydrate as SPA
- **Data flow**: Auth0 token injection → API calls via TanStack Query → React Context for UI state

## Key Files

- `src/routes/` — File-based routing (TanStack Router)
- `src/hooks/` — Domain logic (rides, users, repeating-rides)
- `src/styles/` — Tailwind + per-club themes
- `src/env.ts` — Environment variable validation
- `PLAN_MULTI_CLUB_SSR.md` — Multi-club architecture plan (in progress)
