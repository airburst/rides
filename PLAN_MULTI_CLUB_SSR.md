# Multi-Club SSR + Per-Club Theming Plan

## Context

Transitioning from single-club SPA (Vercel lambda-per-club) to **single containerized deployment serving all clubs via subdomain routing**. Each club will have its own theme CSS file (generated by rides-admin), and the root layout will SSR-inject the correct theme based on the request subdomain. Remaining routes stay SPA hydration for performance.

**Key constraints:**
- No FOUC (flash of unstyled content) — theme must be in initial HTML
- Hybrid SSR: only `__root.tsx` + layout need SSR; routes can stay SPA
- Auth: legacy Auth0 for one club, better-auth for all new clubs
- Builds triggered by new club creation in rides-admin (commits new theme file)
- Future: may consolidate to single shared theme

---

## Approach

### 1. Enable SSR in TanStack Start (Hybrid Mode)

**File:** `vite.config.ts`

- Disable `spa: { enabled: true }` to allow SSR
- Keep route-level SPA enablement for non-layout routes
- Requires `entry.server.ts` for SSR entry point

**Output:** Hybrid app where root layout SSR-renders, nested routes hydrate as SPA.

---

### 2. Subdomain Detection & Club Context

**New file:** `src/lib/club-detection.ts`
- Export `extractClubIdFromHost(host: string): string | null`
- Parses subdomain: `bath.example.com` → `"bath"`, `example.com` → fallback to env var `VITE_DEFAULT_CLUB_ID`
- Used in SSR context (from request headers) and client (from `window.location.hostname`)

**New context:** `src/context/ClubContext.tsx`
- Provides `clubId: string` to entire tree
- Created during SSR with subdomain-detected value
- Hydrated client-side from `window.location.hostname`

**Usage in `__root.tsx`:**
- SSR: receives `clubId` from request headers via `beforeLoad()`
- Client: re-hydrates with `window.location.hostname` during initial load (no mismatch)

---

### 3. SSR Entry Point & Root Layout Refactor

**New file:** `src/entry.server.ts`
```typescript
export default createRequestHandler({
  createHandler: createStartHandler({
    getRouterManifest: () => routeTree,
  }),
});
```

**File:** `src/routes/__root.tsx` (refactor)
- Add `beforeLoad()` hook that runs in SSR:
  - Extracts `clubId` from request headers (via context from entry.server.ts)
  - Validates against a registry (fetch from API or hardcoded allowlist)
- Move `<ClubContext.Provider>` to root
- Inject theme CSS link/style tag into `<Head>`:
  ```tsx
  <Head>
    <link rel="stylesheet" href={`/static/clubs/${clubId}/theme.css`} />
    {/* existing head content */}
  </Head>
  ```
- Update Auth0Provider config to use `clubId` context (for potential subdomain in redirect_uri)

### 4. Per-Club Theme CSS Architecture

**Directory structure:**
```
src/styles/
├── globals.css          ← Shared Tailwind base + utilities
├── themes/
│   ├── bath.css         ← :root { --color-primary: ...; }
│   ├── shrewsbury.css
│   └── _template.css    ← Template for rides-admin generation
```

**`src/styles/globals.css` (refactor):**
- Remove club-specific color vars from `@theme inline { ... }`
- Keep: typography, radius, semantic colors (info, success, destructive, background, foreground, card, etc.)
- Leave `--color-primary`, `--color-secondary`, `--color-accent`, `--color-neutral`, `--color-join`/`--color-leave` for per-club CSS

**Per-club file:** `src/styles/themes/bath.css`
```css
:root {
  --color-primary: #24376e;
  --color-primary-foreground: #ffffff;
  --color-secondary: #831843;
  --color-secondary-foreground: #ffffff;
  --color-accent: #3f60c0;
  --color-accent-foreground: #ffffff;
  --color-neutral: #e5e7eb;
  --color-neutral-foreground: #111827;
  --color-join: #15803d;
  --color-join-hover: #16a34a;
  --color-leave: #b91c1c;
  --color-leave-hover: #dc2626;
}
```

**Build output:**
- Tailwind compiles `globals.css` once → `/assets/tailwind-xxx.css`
- Per-club CSS files copied/processed to `/static/clubs/{clubId}/theme.css`
- At runtime, browser loads both: shared utilities + club-specific vars

### 5. Manifest & Static Assets

**Per-club assets:** `public/static/clubs/{clubId}/`
- `logo.svg` — rendered in header
- `favicon.ico`, `favicon-32x32.png`, `apple-touch-icon.png`
- `theme.css` — loaded dynamically by root layout

**Manifest generation** (optional, future):
- rides-admin can generate `public/manifest.{clubId}.json` or template it at request time
- For now: keep `public/manifest.json` generic or add a small Node middleware to rewrite it per subdomain

---

### 6. Authentication Context (Auth0 + Better-Auth)

**File:** `src/components/Providers.tsx` (refactor)
- Receive `clubId` from `ClubContext`
- Auth0Provider:
  - If legacy club (Bath): wrap with Auth0
  - Otherwise: wrap with better-auth (future)
  - Update redirect_uri if needed: `https://{clubId}.example.com/...`
- Ensure hydration guards remain (`authReady` state)

**Env vars:** Add `VITE_DEFAULT_CLUB_ID` for fallback when no subdomain detected (dev/localhost).

### 7. rides-admin Theme Generation

**Rides-admin output:** When club is created, write file to rides-rides repo:
```bash

POST /api/clubs { name: "Newham Cycling", brandColor: "#...", logoUrl: "..." }
# → commits src/styles/themes/newham.css to rides-rides repo
# → triggers GitHub Actions rebuild
```

**Template for rides-admin:** Create `/src/styles/themes/_template.css`

## Testing Strategy

### Unit Tests
- `club-detection.ts`: Test subdomain parsing (bath.example.com → "bath", localhost:3000 → default, etc.)
- `ClubContext`: Verify context hydration client-side

### Integration Tests
- Root layout SSR with different subdomains
- Verify correct theme CSS injected into response HTML
- Auth0 redirect_uri uses correct subdomain

### Manual Testing
- **Local (SPA mode):** `bun run dev` with `VITE_DEFAULT_CLUB_ID=bath`
- **Local (SSR + subdomain):** 
  - Add `/etc/hosts` entries: `127.0.0.1 bath.localhost shrewsbury.localhost`
  - Run SSR server with `bun run dev --ssr` or equivalent
  - Visit `http://bath.localhost:3000` and `http://shrewsbury.localhost:3000`
  - Verify theme CSS loads correctly, no FOUC
- **Staging (container):** Deploy to container, test subdomain routing via DNS/load balancer

### Verification Checklist
- [ ] `bun run dev` still works (default club)
- [ ] `bun run build` compiles all theme CSS
- [ ] SSR root layout injects correct theme link
- [ ] No FOUC on cold load (theme in initial HTML)
- [ ] Auth0 redirect_uri includes subdomain (if applicable)
- [ ] Remaining routes hydrate as SPA (no full page reload)
- [ ] Per-club assets (logo, favicon) load correctly
- [ ] TypeScript strict mode passes
- [ ] All tests pass
- [ ] Theme CSS cascade works (utilities + vars)

## Future Extensions

1. **Runtime color picker:** rides-admin adds UI editor → generates + commits theme CSS + rebuilds
2. **Dynamic manifest:** Node middleware rewrites `manifest.json` based on subdomain
3. **Shared theme consolidation:** If moving to single theme, remove per-club CSS and keep only globals.css defaults
4. **Database-driven clubs:** Replace file-based theme registry with API lookup (if needed for 100+ clubs)

---

## Rollback Plan

- **If SSR causes performance regression:** Revert vite.config.ts `spa: { enabled: true }`, comment out SSR code
- **If subdomain routing breaks:** Fallback to path-based routing (`/bath/...`) by modifying club-detection.ts
- **If theme injection fails:** Inline all theme vars into globals.css temporarily until fixed
